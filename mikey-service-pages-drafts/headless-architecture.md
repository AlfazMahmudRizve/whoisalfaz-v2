## Who it is for

This service is for a business with a traditional site that is slow to load, hard to maintain, or weak on search, and where the marketing team still needs a CMS they can edit.

It fits a buyer who wants the content editing side kept separate from the front-end code, so editors can work in a CMS while site visitors get a Next.js front end.

## The problem

The current service page puts the problem this way: a standard WordPress site can be slow, insecure, and bloated with plugins, and fighting database queries and server load can hurt Core Web Vitals and SEO.

That wording is from the source page. It is not a claim about every WordPress site, and it is not a measured result for a specific buyer site.

## What is delivered

A headless setup in which content is decoupled from code.

As described on the source page:
- The front end is built in Next.js.
- The marketing team keeps using a CMS dashboard. The source page names WordPress as the dashboard example.
- The front end is hosted on the Edge, as described on the source page.

The aim, as described on the source page, is a fast front end with Core Web Vitals and SEO in mind. No specific load time or uptime result is promised here, because no buyer-specific measurement was verified.
