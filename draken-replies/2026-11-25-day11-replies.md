### C. Architectural Decision on Deployment Model
Regarding your question in Section 4:
> *Deployment model: keep live server Functions (leave the `NEXT_STATIC_EXPORT` flag unset, as the 6 Nov deploy did) or convert all six force-dynamic routes before any static-export build?*

**Authoritative Directive: Leave `NEXT_STATIC_EXPORT` UNSET.**

**Technical Rationale:**
1. **Cloudflare Pages Edge Architecture:** Cloudflare Pages mounts the root `functions/` directory directly (`functions/api/v1/...`). When Wrangler or Cloudflare builds the site, the edge functions in `functions/` handle serverless endpoints natively at Cloudflare's edge.
2. **Next.js Route Handlers Role:** The routes under `src/app/api/...` carry `force-dynamic` because they provide parity for local Next.js development (`npm run dev`) and enable Vitest to execute route integration tests (`routes.test.ts`).
3. **Static Export Conflict:** Running `NEXT_STATIC_EXPORT=true` forces Next.js into `output: 'export'` mode, which by design aborts if any route in `src/app/api/` uses `force-dynamic`.
4. **Reproducible Deploy Path:**
   - Standard build command: `npm run build` (which executes `node scripts/generateSitemaps.mjs && next build` with `NEXT_STATIC_EXPORT` unset).
   - Direct upload deploy: `npx wrangler pages deploy out --project-name=fasttools --branch=master --commit-dirty=false` (or deploying via Cloudflare Pages dashboard with default build settings).
